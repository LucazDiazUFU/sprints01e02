# S1_18 — Branches, merge e fluxo de trabalho

Neste exercício, a branch principal representa a versão integrada. A branch de funcionalidade contém apenas a mudança de uma tarefa, o que facilita verificar o que foi alterado.

```bash
git switch main
git switch -c funcionalidade/status-ativo
git add s1_13.py
git commit -m "Adiciona status de ativos com Enum"
git switch main
git merge funcionalidade/status-ativo
git branch --merged
git log --oneline --graph --all
```

Para simular e resolver um conflito com segurança, duas branches podem editar a mesma frase de um arquivo de teste. Após a tentativa de merge, verifico `git status`, edito a frase final, retiro os marcadores do conflito, salvo, executo `git add` e faço o commit do merge. Não é correto marcar o exercício como executado apenas com esse roteiro: o histórico do repositório deve mostrar os commits e a integração.

O fluxo de trabalho usado é: escolher uma tarefa, criar uma branch, programar, executar o arquivo, registrar o commit, revisar a diferença e integrar. Se o projeto estiver no GitHub, a revisão pode ocorrer por Pull Request.

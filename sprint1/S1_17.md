# S1_17 — Versionamento e colaboração

Uma branch permite desenvolver uma alteração separada da versão principal. O fluxo proposto para o cadastro é criar `funcionalidade/cadastro-ativos`, registrar a mudança e integrá-la após revisão.

```bash
git switch main
git switch -c funcionalidade/cadastro-ativos
git add s1_10.py
git commit -m "Adiciona operações com lista de ativos"
git switch main
git merge funcionalidade/cadastro-ativos
git log --oneline --graph --all
```

Se duas branches alterarem a mesma linha, o merge pode apresentar conflito. Nesse caso, abro o arquivo, escolho o conteúdo correto, removo os marcadores `<<<<<<<`, `=======` e `>>>>>>>`, executo o programa e finalizo com `git add` e `git commit`. A versão final precisa manter o cadastro e a listagem funcionando.

No GitHub, a colaboração segue com a publicação da branch, abertura de um Pull Request e revisão antes da integração. O merge local acima pode ser demonstrado separadamente; um Pull Request só existe após a publicação em um repositório remoto.

Executei o fluxo local: o commit `e7fd86f` foi criado em `funcionalidade/status-ativo` e integrado à branch `main` por merge. Também provoquei e resolvi um conflito entre duas branches no arquivo `exemplo.txt`, registrado em `resolucao_conflito.md`. O histórico está no bundle. A revisão por outro integrante depende de colaboração real.

# S1_19 — GitHub, Pull Requests e revisão de código

O GitHub hospeda o repositório e permite comparar uma branch com a principal. Um Pull Request apresenta a mudança, reúne a discussão e registra a revisão. Antes de aprovar, verifico se o programa executa, se os nomes são claros, se as entradas inválidas são tratadas e se a mudança atende à tarefa.

## Alteração proposta

Publiquei a branch `sprint1/entregas` com os arquivos da Sprint 1 e abri um Pull Request para `main`. O exercício `s1_13.py` faz parte dessa entrega:

> Adiciona uma enumeração para representar os estados Ativo, Inativo e Em manutenção. O programa recebe ID, nome e opção de status, recusa campos vazios e opções fora do menu. Executei o arquivo com opções válidas e inválidas para verificar as mensagens.

## Revisão

1. Conferir o diff para garantir que a alteração se limita à tarefa.
2. Executar o programa com as três opções de status e com uma opção inválida.
3. Verificar se o ID e o nome vazios são recusados.
4. Registrar observações no Pull Request e corrigir problemas antes da aprovação.

O Pull Request apresenta os arquivos para revisão. Comentários e aprovação de outra pessoa dependem da revisão real no GitHub e não foram simulados aqui.

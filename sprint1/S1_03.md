# S1_03 — Critérios de aceitação

Um critério de aceitação mostra uma condição que pode ser verificada ao executar a funcionalidade. Para considerar a tarefa pronta, o programa precisa atender aos cenários de sucesso e de erro, executar sem falhas nos dados previstos e ter o arquivo da atividade disponível.

## Cadastro de ativos

1. Dado que o ID 101 não está cadastrado, quando informo ID 101, nome, tipo, responsável e localização válidos, então o ativo aparece na consulta pelo ID.
2. Dado que o ID 101 já existe, quando tento cadastrar outro ativo com esse ID, então o programa recusa a duplicidade e mantém o registro anterior.
3. Dado que o campo nome está vazio, quando tento cadastrar o ativo, então o programa avisa que o nome é obrigatório e não grava o registro.

## Cadastro de vulnerabilidades

1. Dado que existe o ativo 101, quando cadastro uma vulnerabilidade com grau 7 e dados válidos, então ela fica vinculada ao ativo 101 e aparece na consulta.
2. Dado que o ativo 999 não existe, quando tento registrar uma vulnerabilidade nele, então o programa recusa o cadastro e informa que o ativo não foi encontrado.
3. Dado que o grau informado é 11 ou menor que 0, quando tento cadastrar a vulnerabilidade, então o programa informa que o valor permitido vai de 0 a 10.

## Casos de teste

| Teste | Entrada | Resultado esperado |
| --- | --- | --- |
| T01 | Ativo 101, nome Notebook, tipo Notebook, responsável Lucas, localização Sala 1 | Cadastro confirmado e consulta pelo ID 101 retorna os dados. |
| T02 | Vulnerabilidade 201, ativo 101, descrição Software desatualizado, grau 7 | Cadastro confirmado e classificação ALTA. |
| T03 | Vulnerabilidade 202, ativo 999, grau 7 | Cadastro recusado porque o ativo não existe. |

Esses testes devem ser repetidos após alterações no código. Uma funcionalidade só é considerada pronta quando os resultados observados correspondem aos esperados.

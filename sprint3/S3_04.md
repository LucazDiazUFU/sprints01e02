# S3_04 — Análise de algoritmos e complexidade

Big O descreve um limite para o crescimento do custo conforme o tamanho n da entrada. A contagem de operações permite comparar algoritmos sem depender somente da velocidade do computador.

| Ordem | Exemplo no projeto | Justificativa |
|---|---|---|
| O(1) médio | Buscar ID em dict | Acesso por tabela de dispersão; colisões afetam o pior caso |
| O(log n) | Busca binária | Divide o intervalo ao meio |
| O(n) | Busca linear, filtro, percorrer lista | Visita até n elementos |
| O(n log n) | sorted no pior caso | Combina comparação e organização dos elementos |
| O(n²) | Dois laços completos; Selection Sort | Aproximadamente n vezes n passos |

A busca binária exige uma sequência ordenada. Ordenar apenas para uma consulta pode custar mais do que procurar linearmente. Para várias consultas, a ordenação pode compensar. Um dict é adequado para ID único; uma fila deque atende uma ordem de atendimento.

s3_04.py compara busca linear, busca binária e dois laços com 10, 100 e 1000 elementos. O arquivo evidencias/s3_04.txt contém a tabela real. O espaço auxiliar também importa: copiar uma lista exige O(n); a busca binária iterativa exige O(1).

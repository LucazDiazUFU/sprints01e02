# S3_12 — Erros numéricos

Nem todo decimal tem representação binária finita. Em float, 0.1+0.2 resulta 0.30000000000000004 e a igualdade direta com 0.3 falha. np.isclose permite comparar com tolerâncias explícitas. Tolerância deve seguir a escala do problema; não deve aceitar qualquer diferença.

Erro absoluto é |aproximado-real|. Erro relativo é erro absoluto/|real|, quando real é diferente de zero. Para π, truncar a três casas dá 3.141, erro aproximado 0.000592654; arredondar dá 3.142, erro 0.000407346. Erros relativos ficam aproximadamente 0.000188647 e 0.000129662. A evidência inclui os valores calculados.

O exemplo soma dez parcelas de 0.1 com sum. O Python 3.12 usa uma soma aprimorada de floats. Nesta execução, o resultado final foi exatamente 1.0; isso não demonstra ausência geral de propagação. Alguns arredondamentos se compensam. É preciso observar o algoritmo concreto.

B=[[1,1],[1,1+10⁻¹⁰]] tem determinante aproximadamente 10⁻¹⁰ e número de condição aproximadamente 4·10¹⁰. Para b=(2,2+10⁻¹⁰), a solução é (1,1). Perturbar o segundo termo em 10⁻⁸ gera aproximadamente (-99,101). Um resíduo pequeno não garante pequeno erro na solução de um sistema mal condicionado.

np.linalg.solve evita formar a inversa explicitamente. No exemplo registrado, tanto solve quanto inv deram resíduo zero. O projeto verifica posto e condição, resolve e registra o resíduo.

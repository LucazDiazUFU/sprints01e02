# S3_18 — APIs REST e testes de integração

A API organiza recursos por URLs. GET lê; POST cria; PUT substitui os campos obrigatórios do ativo; PATCH altera parte; DELETE exclui após confirmação. POST retorna 201, leitura e atualização 200, exclusão 204 sem corpo. Entrada inválida retorna 400, credencial ausente/incorreta 401 quando configurada, recurso inexistente 404 e conflito 409.

| Recurso | Operações |
|---|---|
| /api/ativos | GET e POST |
| /api/ativos/{id} | GET, PUT, PATCH e DELETE |
| /api/ativos/{id}/vulnerabilidades | GET e POST |
| /api/vulnerabilidades/{id} | GET, PATCH e DELETE |
| /api/ativos/{id}/dependencias/{origem} | PUT e DELETE |
| /api/riscos | GET; ponderar opcional |
| /api/exportacao | GET, lista de objetos |
| /api/importacao | POST, lista validada integralmente |
| /api/saude | GET, banco e tempo ativo |

DELETE exige JSON {"confirmar":true}. A coleção postman.json contém requisições e testes de resposta. Use uma base de demonstração vazia, pois os IDs 991 e 992 serão criados e excluídos. A variável token fica vazia por padrão e pode receber a credencial local.

tests/test_trabalho2.py cobre a integração HTTP, cadastro, SQL e recarga. A documentação do Flask orienta o cliente de teste: https://flask.palletsprojects.com/en/stable/testing/. A execução do Postman pelo estudante permanece uma forma de conferir visualmente as requisições.

# S3_06 — Qualidade de software e código limpo

O CRUD anterior foi reaproveitado em vez de reescrever suas validações. Modelos representam dados, cadastro aplica regras, armazenamento grava, risco calcula e API atende HTTP. Isso evita colocar regras de entrada no JavaScript e deixar o servidor aceitar valores inválidos.

O arquivo refatoracao.py mostra o mesmo filtro antes e depois. Antes havia dois ifs aninhados; depois há uma condição conjunta em uma compreensão. Os dois retornam nomes do mesmo tipo com status ATIVO. O teste de equivalência inclui ativos de tipos e estados diferentes.

Black padroniza a formatação; flake8 identifica problemas de estilo e uso; pylint ajuda a identificar problemas de organização. A configuração dispensa docstrings porque a explicação fica nos relatórios e os códigos foram solicitados sem comentários. Os limites de argumentos acomodam os campos do CRUD. Uma nota alta não comprova ausência de defeitos.

As evidências de qualidade registram os comandos e seus resultados. A correção real encontrada pelos testes foi uma contagem errada de parâmetros no INSERT de vulnerabilidades, explicada em S3_07.md. Não foram criadas falhas fictícias para apresentar uma refatoração.

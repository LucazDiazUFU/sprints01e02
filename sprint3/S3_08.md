# S3_08 — GitHub, pull requests e integração contínua

A entrega usa uma branch própria, sprint3/entregas, partindo da branch sprint2/entregas. Um pull request apresenta as mudanças para revisão, mantendo o histórico anterior. A revisão do estudante e do docente não é substituída por testes automáticos.

O workflow .github/workflows/sprint3.yml está configurado para execução manual, para não rodar a cada envio. Quando acionado, instala dependências, confere Black e flake8, executa pylint e pytest com cobertura. Um segundo job monta a imagem Docker e verifica /api/saude. Os resultados efetivos devem ser consultados na aba Actions.

O exercício local de conflito está em evidencias/conflito_git.txt. Duas branches alteram a mesma linha; o merge produz marcadores de conflito. A resolução escolhe um texto coerente, remove os marcadores, adiciona o arquivo e cria um commit. Em trabalho real, a decisão deve considerar as duas alterações e conversar com seus autores.

A branch e o pull request permitem conferir arquivos, commits e verificações.

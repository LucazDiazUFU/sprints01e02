# S3_07 — Estratégias de teste e testes unitários

Os testes usam unittest e pytest. Cada caso cria dados temporários, sem acessar o inventário pessoal. Há cenários de cadastro válido e inválido, ID e nome repetidos, atualização, exclusão, vínculos, JSON ilegível, recarga, rollback SQL, conflito de versão, risco e API.

Teste unitário verifica uma unidade pequena, como ordenação ou validação. Integração verifica unidades trabalhando juntas: requisição HTTP, regra de cadastro e SQLite; ou objeto, JSON e recarga. O cliente de testes do Flask exercita a API sem depender de um navegador.

Falha encontrada: a tabela vulnerabilidades tem dez colunas, mas o INSERT tinha onze marcadores. Cinco testes falharam, incluindo persistência e cadastro pela API. A instrução passou a ter dez marcadores. Os testes de gravação, atualização e recarga passaram após a correção. Também foi ajustada a edição no terminal para preservar CVSS 0 ao pressionar Enter.

A execução e a cobertura estão em evidencias/testes.txt e evidencias/cobertura.txt. Cobertura mede linhas executadas pelos testes; não prova correção e não deve ser confundida com exercícios executados separadamente. As telas e os caminhos interativos do terminal exigem conferência manual adicional.
